1. 문제 정의

조직문화 업무에서 반복적이고·검토에 시간이 많이 들며·사람 확인에 의존하는 지점을 찾습니다. (구성원 300명 생일 선물 발송: 음력 생일 환산 / 동명이인 식별)

항목내용
담당 업무 & 현황

조직문화 담당자가 구성원 300명(양력·음력 생일자 혼재)의 생일 선물을 매월 발송하고 있음.

음력 생일은 매년 양력 날짜가 달라 해마다 변환·검토가 필요함.

핵심 문제
(Pain Point)

① 음력→양력 변환·검토를 매년 수작업으로 진행 (연 [ ]시간 소요, 윤달·말일 오류 위험)

② 동명이인을 Knox ID/사번으로 건마다 재조회 (월 [ ]건)

③ 입퇴사·부서이동 반영 지연으로 누락·오발송 가능성

의사결정 질문이번 달 생일 선물을 누구에게, 언제 보내야 하는가? (동일인 여부·재직 여부·양력 환산일 확인)
현재 판단 근거와 한계담당자 경험과 수기 확인에 의존, 이름 기반 조회라 동명이인 구분이 사후적, 변환 결과를 검증할 기준 데이터 없음
선정 과제음력→양력 자동 변환 + 사번 기반 식별 + 월별 발송 대상·검토 리포트 자동 생성

2. AI PoC 설계

항목내용
PoC 목표 & 가설가설: 사번을 고유키로 쓰고 음력→양력 변환을 공식 데이터로 자동화하면, 연간 검토 시간을 80% 이상 줄이고 동명이인 재조회를 없앨 수 있다.
적용 범위

대상: 구성원 300명 전체 (음력 생일자 [ ]명 포함)

품목: 월별 생일 선물 발송

기간: PoC 4주 (2027년 연간 생일 캘린더 생성 + 익월 발송분 시범 운영)

활용 데이터

인사 명단(사번·Knox ID·이름·부서·재직상태), 본인 등록 생일(양/음력·윤달 여부), 음양력 변환 기준 데이터(한국천문연구원 공공 API 등), 연도별 발송 이력

※ 개인정보이므로 접근 권한 제한, 사내 승인된 저장소에서만 처리

AI 적용 방식

날짜 변환은 AI가 아닌 공식 데이터·코드로 처리(LLM 직접 계산 금지)

Claude 활용: ① 엑셀 데이터 정제·동명이인 후보 점검 ② 예외 항목(윤달·29/30일·휴직) 분류 ③ 월별 검토 리포트·축하 문구 생성

출력물 & 사람 개입 지점

월별 발송 대상 리스트(사번·Knox ID·부서 병기) + 예외 항목 표 → 최종 발송 확정은 담당자 승인

윤달·말일·주말 처리 정책 미정 건은 담당자가 판단
